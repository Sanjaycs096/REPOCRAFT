# GitHub Presentation & Branding Policy

This reference governs **Phase 2: GitHub Repository Presentation & Branding Audit**.

---

## 1. Professional Presentation Criteria

A professional open-source or product-based repository presentation requires:
- Clear project identity with an informative title and tagline.
- Concise GitHub About description reflecting actual project capabilities.
- Relevant ecosystem and domain topics/tags to aid discoverability.
- Authentic visual media: genuine screenshots, diagrams, and project logo.
- High-fidelity architecture diagrams (using standard Mermaid syntax).
- Accurate badges: every status badge must link to verified workflows or registries.

---

## 2. Local vs. Remote Distinction

RepoCraft strictly categorizes presentation actions:
- `LOCAL_RECOMMENDATION`: Guidance for local files (README additions, Mermaid diagrams, logo placement, local image capture specs).
- `REMOTE_METADATA_ACTION`: Operations targeting the GitHub API or repository settings (topics, about description, social preview cards, homepage URLs).

---

## 3. Remote Action Restrictions

In Phase 2:
1. **Remote Actions Are Blocked**: RepoCraft does NOT perform external GitHub API mutations in Phase 2.
2. **No Repository Name or Visibility Changes**: RepoCraft never modifies repository names or toggles visibility.
3. **No Releases or Tags**: Creation of GitHub releases and tags is strictly prohibited in Phase 2.
4. **Screenshot Integrity**: Never fabricate application screenshots or mockup images. When a screenshot is missing, RepoCraft generates exact resolution and view capture requirements for the maintainer.
